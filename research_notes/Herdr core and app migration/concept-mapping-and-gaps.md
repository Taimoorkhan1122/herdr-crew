# Herdr core and app migration: concept-by-concept mapping and gaps (for full replacement)

This is a read-only mapping based on observed CLI/help text, existing code in `bin/crew`/`lib/*`, ADRs 0002/0008, tests, and live state. All claims are cited with file paths/command surfaces. Inferences are called out separately.

## Scope
- Old: `herdr` (0.9.5) multiplexer (workspaces/tabs/panes/agents managed via `herdr ...` JSON APIs)
- New: `hc` (herdr-core 0.1.16) as terminal runtime/orchestrator; `herdr-app` (0.1.11) as UI/layout controller
- Target: migrate `bin/crew` (706 lines) fully to new model with `herdr-app` required

## Primitive mapping

| Old concept (herdr) | New equivalent | Exact commands/APIs | Behavioral differences | Status (clean/workaround/gap) | Notes / citations |
|---|---|---|---|---|---|
| Workspace (`workspace` in herdr) | Space (herdr-app model) / `hc` has no global workspace concept; runtime is per-core. `herdr-app` spaces map to cores/machines. | Old: `herdr workspace list/create` (bin/crew:201-215 uses `herdr workspace list`, `herdr workspace create --label crew-$SLUG --cwd $REPO --no-focus`). New: `herdr-app do space.new --name ... --folder ... --machine ...` (apps/AGENTS 506-510). hc has no workspace mgmt. | IDs differ (old `w*`, spaces have own IDs). Spaces are per machine; remote via `--machine`. `herdr-app` stores layout in core's `herdr-app` document (AGENTS ~110-150). Old workspace had cwd/label; space has folder/name/machine. | Workaround | crew targets a workspace via `HERDR_WORKSPACE_ID` or creates `crew-$SLUG` outside Herdr (bin/crew:202-215). With app required, spaces are app-controlled; `hc` doesn't create spaces. |
| Tab (`tab`) | Tab (herdr-app) | Old: `herdr tab create --workspace $WS --cwd $cwd --label ... --no-focus "${EV[@]}"` (bin/crew:332-340, 422-424). New: `herdr-app do tab.new --name ... --space ... --folder ... --argv ... --task ...` or created implicitly by space/terminal. `herdr-app` tabs have IDs; `tab.close/rename/move/select/settle`. | Old crew creates tab and gets root pane id from response. New app creates tabs/spaces; crew must use app commands or rely on labels. `tab.create` in old took `--env` per pane; new model: env injection is different (see below). | Workaround | Layout is app-driven. Crew currently relies on `herdr tab create` returning root pane; in new model that becomes `herdr-app` orchestration or `hc` + labels. |
| Pane (`pane`) | Pane (herdr-app model) / terminals live in `hc` | Old: `herdr pane split $root --direction right --cwd $cwd --no-focus "${EV[@]}"` (bin/crew:336-340,427-428). `herdr pane run $board "tsk"` (340). `herdr pane report-metadata ...` (476). New: `herdr-app do pane.split --direction right --pane p12` (apps/AGENTS 525-530). `hc` runs programs in terminals (`hc run`); panes are UI concept. | Old: env passed to split/create. New: labels connect terminals to spaces/tabs (`herdr.space=<id>`, `herdr.tab=<id>` per AGENTS 136-147). `hc` has no pane split API - splitting is app-level. `pane.run` becomes `hc run` in context of terminal/pane managed by app. `pane.report-metadata` has no direct `hc` equivalent in help; app may show terminal status differently. | Gap/workaround | Major shift: layout control moves to `herdr-app do` (app required). Crew currently does low-level pane splitting; must switch to app commands or let app manage layout. |
| Agent (herdr agent) | Terminal running agent in `hc`; identity via labels/status | Old: `herdr agent start $name --pane $pane --timeout 120000 "${args[@]}"` with kind/args (bin/crew:239-288). `herdr agent prompt "$1" "$2"` (220), `herdr agent wait`, `herdr agent get` (status), `herdr agent read`, `herdr agent send-keys` (227), `herdr agent rename --clear` (120). New: `hc run --bg --name ... <template/agent> ...` (hc skill). Talk via `hc send/wait/read/keys/interrupt`. Status comes from OSC 7501 reported as `status` on terminal (hc get/ls show status). `hc` has no `agent rename` in same form; naming is via `--name` and labels. | IDs: old used agent names unique among live agents; new uses terminal addresses `t*` and names. Focus/blocked semantics differ (hc notes: blocked means person needed, `send` refuses unless `--force`; hc skill details). First-message delivery: old did `submit()` which retries Enter if needed; new says put task in `run` args/templates or wait for readiness then `hc send` (hc skill). Env inheritance: old passed env to pane/agent start; new relies on shell/env and labels; `CREW_*` must be injected differently. | Workaround/gap | Conceptual shift from "agent as managed entity" to "terminal running agent". Crew logic around agent lifecycle needs rewrite. |
| `agent start` | `hc run` / template | Old: complex start with kind/args/settings/hooks (bin/crew:239-288). New: `hc run --bg --name <name> --cwd <dir> <template|cmd>` (hc skill). Templates in `~/.config/herdr-core/templates/*.md`. | Old could pass `--kind opencode/claude` with specific args/hooks; new uses templates/interactive agents directly. OpenCode/Claude integration differs. | Workaround | Need to map crew's agent kinds to hc templates or direct commands. |
| `agent prompt` | `hc send <t> <text>` (and may need readiness) | Old: `herdr agent prompt "$1" "$2"` then retry logic (220-235). New: `hc send <t> <text>`; put first task in `run` when possible (hc skill says "put the first task in `run`: a send to a booting agent can be dropped"). | Bracketed paste/Enter retry behavior differs. New warns about first message delivery. | Workaround | Submit logic needs adaptation. |
| `agent wait` | `hc wait <t>` / `hc wait --children` | Old: `herdr agent wait "$1" --until working/blocked/done` (224, 277). New: `hc wait <t>` waits until it stops working or exits; `hc wait --children all/any` for children. | Semantics differ (plain programs wait for exit; agents have status). Reason codes differ (message/timeout). | Workaround | Need to map wait conditions. |
| `agent read` | `hc read <t> [--lines N]` | Old: `herdr agent read "$1" --source visible/recent-unwrapped` (225, 273). New: `hc read <t> --lines N` prints screen+history (text by default). | Source flags differ; "detection" source mentioned in app context not same as hc. | Workaround | Mostly compatible conceptually. |
| `agent list/get` | `hc ls` / `hc get <t>` | Old: `herdr agent get "$1"` returns agent_status/pane_id (108,114). New: `hc ls` lists terminals with status/app/state; `hc get <t>` shows details including status. | Old had agent-centric view; new terminal-centric. | Workaround | Need to map agent names to terminals. |
| `agent rename` | No direct equivalent | Old: `herdr agent rename "$1" --clear` (120). New: naming via `--name` on `hc run`; no rename/clear command shown. | Gap | Crew uses rename to reclaim stale names (bin/crew:111-121). No replacement visible. |
| `agent send-keys` | `hc keys <t> <keys...>` | Old: `herdr agent send-keys "$1" enter` (228, 276). New: `hc keys <t> enter esc up ctrl+c` (hc skill). | Similar. | Clean replacement (mostly) | Need to confirm key naming matches. |
| `pane run` | `hc run` in terminal context / `herdr-app` terminal.open | Old: `herdr pane run "$board" "tsk"` (340). New: `hc run --bg --name web bun dev` runs programs; in app context, `terminal.open` or `tab.new` can start things. But layout is app-controlled. | Old ran command in existing pane; new runs in terminal managed by hc/app. | Workaround | Board (tsk) placement becomes app layout concern. |
| `pane split` | `herdr-app do pane.split` | Old: CLI split with env/cwd/ratio. New: app command only (apps/AGENTS 525-527). `hc` has no split. | Layout control moved to app. Env injection different. | Workaround/gap | Crew must use app API; requires app running. |
| `pane report-metadata` | No obvious equivalent | Old: `herdr pane report-metadata "${HERDR_PANE_ID:-none}" --source crew --title "$T $ME: $note"` (476). New: no command found in help. App shows terminal status/labels; maybe labels or different mechanism. | Gap | Used for pane titles like `T7 driver: started` (bin/crew:476, test expects it). No replacement visible. |
| `tab list/close` | `herdr-app do tab.close` / `herdr-app ls` | Old: `herdr tab list --workspace ...`, `herdr tab close "$tab"` (510-515). New: `herdr-app ls` inspects; `herdr-app do tab.close --id ... --confirmed true` (apps/AGENTS 517-520). | App API shape differs (JSON args). | Workaround | Crew needs to switch to app commands. |
| `workspace list/create` | `herdr-app do space.new` / `herdr-app ls` | Old: as before. New: space commands. | Different model. | Workaround | As above. |
| `watch` (crew) polls `tsk` + `herdr agent get` | Still possible via `tsk` + `hc ls/get`; `hc events` exists | Old: cmd_watch polls tsk and agent status (530-586). New: `hc events` follows changes live (hc help). | Can adapt to hc events + tsk. | Workaround | Replace agent polling with terminal/hc events. |
| `status` | `hc ls` + `tsk` | Old: probes agent names via `herdr agent get` (489-504). New: `hc ls` gives terminals; map names to terminals. | Need name->terminal mapping. | Workaround | Possible if naming/labels preserved. |
