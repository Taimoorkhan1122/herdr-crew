# Per-project agent and role configuration

Status: user approved per-project configuration and the configure entry point in the main conversation. Implementation choices below are the builder's decisions; they do not imply approval for publication or live agents.

Users run `herdr-crew configure` in a project to assign installed agent CLIs and optional models to ranks or individual jobs. `.herdr-crew.json` is an editable JSON file in the primary project checkout, shared by its linked worker worktrees. Configuration is project-specific; user-wide defaults are deferred. Existing projects without this file retain their current rank/model/effort defaults.

The file has `version: 1` and a `roles` object keyed by rank or job name. Each override has `agent`, optional `model`, and optional `effort`. A job overrides its rank. Changing agent clears provider-specific inherited model/effort settings; omitted values otherwise retain the same runtime's inherited settings. `inherit` explicitly selects that provider's own defaults. Invalid fields, roles, types, unsupported agents and unsupported effort values fail before tasks, worktrees or panes are created. Configuration is data, never shell code. Writes are atomic, preserve unrelated role assignments and refuse symlink destinations. Configure accepts flags/arguments for automation as well as an interactive human setup. `configure --show` displays resolved assignments and requires no live Herdr/tsk or agent invocation.

Initial supported adapters are Claude Code and OpenCode, the two runtimes already represented in the launcher. Enable OpenCode only with explicit native role permissions, instructions and safe startup options verified against the installed CLI and primary documentation. Other Herdr kinds need a permission/lifecycle adapter before configuration can select them: merely passing `--kind` is insufficient. Do not silently fall back to Claude or weaken rank rules. Codex and Gemini were investigated, but unverified permission parity is not acceptance evidence.

Claude keeps native rank files, settings hooks, model/effort flags and member push/merge denies. OpenCode receives session-local generated configuration and common rank/persona instructions; read-only ranks retain tool restrictions and command allowlists, members retain edit access and push/merge denies. Provider-specific helper/skill/context guidance must be explicit, without claiming Claude hooks or tool names exist elsewhere. No global agent config or target project instruction files are overwritten.

The resolved agent, model and effort are saved with the existing per-agent runtime metadata. Restart uses that saved selection even if project settings change; legacy Claude metadata falls back to current defaults; legacy OpenCode metadata without a native session policy is refused. Unsupported startup/trust behavior must fail with an actionable error instead of applying Claude-specific keystrokes. Existing worktree ownership, naming, messaging and handoff contracts remain intact. Existing handoff-path race is separate and remains documented.

Verification uses disposable HOME/projects and fake Herdr/tsk/agent executables, real Git for config sharing, per-argument assertions for permission config, and the existing launcher/worktree suites. No real agents or billable sessions are launched. Independent final source review checks configuration trust boundaries, provider inheritance, policy generation and restart stability.
